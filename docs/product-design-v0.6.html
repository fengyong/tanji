探记 TanJi
探店达人的行程与收款

一个纯本地的 iOS 工具：把「接单—排期—到店拍摄—出片送审—发布—收款—催收」这条原本散落在微信聊天、备忘录和 Excel 里的流水线，收进一个人一天能真正用起来的 App。本文件从已实现代码反推产品意图，还原信息架构、 状态机、交互规则与界面原型。

文档版本 v1.0 对应产品 v0.6（多账号版） 2026-11-24 平台：iOS 原生 / Web PWA 形态：纯本地 · 无服务端 · 买断制
01

产品概览OVERVIEW

先回答三个问题：这是给谁做的、替掉了什么、凭什么比现有做法好。

📅
一句话定位

探店达人自己的「行程表 + 交付看板 + 应收账款」，一个 App 管完从接单到回款的全流程。

🎯
要解决的三件事

档期撞车与漏拍、片子出没出齐说不清、尾款拖到不好意思催。

🔒
产品底线

数据只存本机、不上传、不注册、不联网也能用；随手能导出带走。

1.1 它替掉了什么

现有做法具体痛点本产品的对应解法
微信聊天记录接单信息埋在对话里，翻不到；报价、要求、地点各说一半一次录入结构化成订单：商家/地点/组队/出片要求/总价定金/联系方式，全字段可搜索
手机日历只记得「几点去哪」，不记得这单多少钱、收没收、片发没发日历与金额、状态、收款同源；同一天多条自动打点，忙日/爆单/千元日给勋章
备忘录/脑记「某某店尾款还没给」→ 想起时已经欠了两个月账期从实际拍摄日自动起算，超阈值进逾期池，每天 09:00 汇总提醒
Excel 对账月末手敲一遍，漏单、错行、版本混乱打开即统计；CSV 29 列 / JSON 备份 / 真 .db 三种导出，随时交给会计或自己归档
多账号切换手上带 2–3 个达人号，报名资料每次重打，收入混在一起账号作为一等对象：订单挂账号、五页（首页/行程/订单/收款/统计）可合并或拆分查看、资料一键拷贝去报名

1.2 价值主张：三条线各自闭环

① 日程线 —— 不撞单

月历 + 未来 7 天 + 当日清单三层视图；新建时同日 ±2 小时给冲突提示（带地点，只提示不拦截）；左右滑动切日。

② 交付线 —— 不漏片

拍摄 → 提审 → 副片/正片 → 发布五节点；按单配置正/副片要求，不需要的节点自动消失；超 24h 未出齐红角标 + 本地通知。

③ 资金线 —— 不少钱

定金/尾款双轨；私收与平台结算分开处理；逾期分桶（≤7 / 8–30 / 30+）；催收痕迹与 1/3/7 天备忘；每笔记账可撤销。

产品判断：这是一个「个人作业系统」，不是 SaaS。因此所有设计都服从两条约束 —— 零配置上手（不建团队、不配流程、不登录）与零信任外部（数据不离机）。 任何需要服务端才能成立的功能（多人协作、云同步、平台账单直连）都被有意排除在 v0.6 之外。

02

用户与场景USERS & SCENARIOS

产品只服务一类人：靠「到店拍摄 + 出片交付」换钱的个人创作者。他们的共同特征是 —— 单量不大（日均 1–5 单）、 档期由商家定、钱分两笔收、交付有明确验收标准、且同时给多个服务商/多个账号干活。

次级画像与使用差异

  • 兼职达人：每周 2–5 单，只看首页够用；对多账号、统计无感，需要「打开就懂、不学」。
  • 小团队主理人：自己拍 + 带 1–2 个搭档，需要组队字段与「按账号拆开看」来分账。
  • 服务商对接人（非用户但受影响）：会收到达人发来的「今日行程图」与「账号资料」，因此分享物必须干净、不含金额。
设计推论：单账号用户必须感受不到多账号的存在（≥2 个账号才出现筛选条与选号卡）； 所有高频判断都收在首页一屏内，次级功能（统计、数据管理）沉到第 5 个 Tab。

2.3 场景→痛点→需求推导

摩擦点 A：接单要滚两屏

谈单发生在微信里，30 秒要回话。11 个字段一次性摊开，用户在第 6 个字段就开始不耐烦，最后只填商家和价格 —— 地点、组队、出片要求全丢，后面拍摄和交付只能靠记忆。

产品回应：必填只留商家 + 总价；账号/服务商/类型/时间/出片要求全部给默认值或点选；保存条固定在底部，随时能按；冲突提示放在时间行下方而不是保存时才弹。

摩擦点 B：待发片必须逐单进详情

一晚处理 3 单，原路径是「点行 → 详情 → 点标记 → 关闭」×3，9–12 次点击，且中间容易被其他信息打断。

产品回应：把「下一步该做什么」提到列表层（提审 → 副片 → 正片 → 发布），行尾一个按钮直接完成；首页只展示 4 条并给「还有 N 单」出口。

摩擦点 C：随时要用的信息拿不走

在车上要导航、要把地址发给司机、月底要交表格 —— 地址是死文本、账号资料要重打、对账靠手抄。

产品回应：地点行「导航」（手填地址优先，没填退到 GPS）；账号「一键拷贝」（昵称 + 抖音 + 手机）；CSV 29 列覆盖全链路。

摩擦点 D：催收是社交行为，不只是记账

真实动作是「问一次 → 对方说 X 号给 → 到点再问」。只记一个「下次提醒」，等于每次都从零开始问，还容易漏掉对方承诺的日期。

产品回应：催收跟进痕迹（时间 + 对方答复，≤50 条）+ 快捷答复芯片 + 1/3/7 天备忘；备忘到期前首页不再红脸催。

03

需求清单REQUIREMENTS

按模块给出用户故事与验收标准。P0 = 每天都在用，缺失即不可用；P1 = 每周会碰；P2 = 月度级 / 增强。 标 已实现 的条目即当前 v0.6 交付范围。

编号优先级用户故事验收标准
US-01P0作为达人，我要在 30 秒内记下一单，这样我能在微信里立刻回话。仅商家与总价为必填；其余有默认值；保存条常驻底部；保存后跳到该单日期的行程页。
US-02P0作为达人，我要在录单时立刻知道这单会不会撞档期。同日 ±120 分钟内的已有单以横幅列出「时间 + 店名 + 地点」；只提示不阻止保存。
US-03P0作为达人，我要在到店时一次动作完成「打卡 + 记录拍摄时间」。随手拍一张即写 shotAt；同时静默记录 GPS，失败不阻断；金额格铺该图淡化底图。
US-04P0作为达人，我要在列表上直接推进交付流程，不必逐单进详情。首页/订单页行尾按状态给唯一「下一步」按钮：提审 / 发副片 / 发正片 / 发布。
US-05P0作为达人，我要清楚哪些单超 24 小时还没出齐片。拍摄满 24h 且未按配置出齐 → 列表红角标「超24h」+ 一次性本地通知；出齐/删单后自动撤销。
US-06P0作为达人，我要能记定金与尾款两笔钱，并知道还差多少。定金/尾款分别记账，仅记录渠道（微信/支付宝/银行卡/抖音商单/其他），不做真实支付；重复收款被拦截。
US-07P0作为达人，我要一眼看到谁欠我钱、欠了多久。首页告警卡三态；收款页按 ≤7 / 8–30 / 30+ 分桶；逾期天数从实际拍摄日起算。
US-08P1作为达人，我误点「已收」后要能立刻撤回。记账成功 Toast 带「撤销」；仅在订单标记与流水未被改动时可回滚，否则提示。
US-09P1作为达人，我要记下「催过几次、对方怎么答」，并让它在几天后再提醒我。跟进痕迹含时间与答复（≤50 条，展示最近 4 条）；1/3/7 天备忘生成一次性本地通知；到期前首页不再红催。
US-10P1作为达人，我要给抖音商单填一个「平台预计到账日」。过期未到账时详情/收款页标红显示「已超 N 天」；平台单永不计入逾期催收。
US-11P1作为达人，我要在行程页一眼看出这周忙不忙。「未来 7 天」横滑条显示每天单量与成交额；点击跳该日、跨月自动翻月。
US-12P1作为达人，我要在列表里按地点/联系人/服务商/备注找回旧单。搜索覆盖商家、地点、联系人、服务商、组队、备注、类型；拼音输入法合成期间不打断。
US-13P1作为多号达人，我要把订单分开看，也要能合起来看总额。≥2 账号时首页/行程/订单/收款/统计五页都出现账号筛选条；选「全部」合并，选某账号只数该账号的单与流水；收款页角标随筛选变化。
US-14P1作为多号达人，我要一键拷贝账号资料去报名。拷贝内容含昵称、抖音号、手机号；成功后 Toast 明确告知已拷贝。
US-15P1作为多号达人，我要一次给多个账号建单（同店同日多号发）。建单选号支持多选，每个账号各生成一笔独立订单，编号连续且独立维护。
US-16P2作为达人，我要在给服务商/搭档看行程时不暴露金额。行程分享图默认不含任何金额，跟随当前账号筛选；底部标注「不含金额信息」。
US-17P2作为达人，我要在别人看屏幕时隐藏金额。顶栏眼睛一键隐藏所有金额；隐藏态下编辑弹层金额字段只读并说明原因。
US-18P2作为达人，我要在换机/丢机后能恢复数据。JSON 备份导出/导入（≤10MB，导入前预览并校验流水一致性）；替换前自动留一份可撤回备份。
US-19P2作为达人，我要能识别「哪套是演示数据」。工作/演示两套数据独立存储、互不覆盖；工作/演示标记显示在顶部；演示模式不排真通知。
US-20P2作为达人，我要批量把历史单挂到某个账号下。统计页「批量改挂」列出账号与各自单量，一次把全部未指定订单挂到所选账号。
明确不做（v0.6 范围外）：登录与云同步、团队协作与派单、真实支付通道、平台账号授权抓单、账单自动导入、多端实时同步。 这些都会破坏「纯本地、零配置、买断」的产品承诺，或在没有服务端的前提下无法保证一致性。

05

状态模型与业务口径STATE MODEL

订单有两条互相独立、但共同决定「这单到什么程度了」的状态线。所有展示文案、筛选、角标、通知都由这两条线推导， 不允许各页面自己算 —— 这是产品口径唯一真源的意义。

5.1 工作线（交付进度，四态）

待拍摄→ 后期中→ 发片中→ 已交付
判定：无拍摄时间 → 待拍摄；已拍未提审 → 后期中；已提审但按该单配置未出齐 → 发片中；出齐 → 已交付。

5.2 资金线（回款进度，四态）

待定金→ 待尾款⇢ 平台结算→ 已结清
「待尾款」与「平台结算」是同一层的两个分支：私收走催收，抖音商单走平台到账日，永不计逾期。两者都收齐后 → 已结清。

5.3 五个里程碑与前置依赖

节点字段前置规则

正向：只推「唯一的下一个动作」

详情页主操作区永远只返回一个按钮（拍完 → 提审 → 副片 → 正片 → 发布）， 用户不需要判断「我现在该点哪个」。列表层的行内按钮复用同一套判定，只是把动作前移到行尾。

反向：清除会截断下游

任何节点都允许清除，但清除一个上游节点时，其后的所有记录一并清空， 并事先告知将被清掉哪些。避免出现「未拍摄却已发布」这类自相矛盾的时间线。

催收阈值默认 15 天，可选 7 / 15 / 30 / 45；超过即进逾期池不同服务商结算周期差异大，阈值可配置比写死更实用

核心旅程USER JOURNEYS

六条主旅程覆盖 95% 的日常操作。每条给出：触发时机、操作步骤、系统反馈、异常分支。 界面细节见下一章的原型标注。

J1

微信接单 → 建预约

目标：30 秒内记完，且不撞档期
  1. 首页/行程/订单任意页点右上「+ 预约」，底部弹层升起（保存条已在底部常驻）。
  2. 填品名/商家与总价——只有这两项必填，其余按默认值走。
  3. （多账号时）在「账号」区点选卡片，可多选；每个选中账号会各生成一笔独立订单。
  4. 「服务商」点预设芯片（蜂向/小爱/金城/食物/直客），自定义输入保存后自动进预设。
  5. 选日期时间 → 下方立刻出现冲突横幅：列出同日 ±2h 的时间、店名、地点，不阻止保存。
  6. 点底部「保存预约」→ 自动跳到该日期的行程页，Toast 确认。 反馈：单品 →「已添加预约：店名」；多账号 →「已添加 N 笔独立预约」
异常与边界
  • 总价/定金非法：非数字、超过两位小数、定金 > 总价 → 行内红字拦截，不关弹层。
  • 正副片都没勾：「出片要求至少要勾选正片或副片」—— 否则交付线永远无法判定完成。
  • 多账号一个都没选：提示「请至少选择一个账号」。
  • 编号上限：订单号需 < 100000（通知 id 分段依赖），达上限提示先导出备份。
  • 时段相对日：选日期后右侧显示「今天 / 明天 / 3 天后」，避免手滑选错月。
J2

到店打卡 → 记录拍摄

目标：一个动作同时完成到店证明与状态推进
  1. 首页「今日拍摄」找到这一单，行尾点「打卡」（不拍照也可）。
  2. 要留证据则进详情点「📷 随手拍 · 到店门口来一张」，拍一张即可。
  3. 系统做三件事：写入 shotAt（若尚未拍）、生成淡化小图入库、静默记录 GPS。
  4. 金额格立刻铺上该图作为底图 —— 列表扫一眼就能分出「去过店」和「还没去」。 反馈：「已随手拍 · 拍摄时间已记录」/「已记录到店定位 ✓」
  5. 拍摄完成后，该单进入 24h 出片倒计时，同时排一次本地出片提醒。
异常与边界
  • 拒绝定位/无信号：静默失败，不影响「已拍摄」，详情页可手动「记录当前位置」补。
  • 重拍：覆盖旧图与 GPS —— 重拍语义是「我又到店了」，以最新为准。
  • 图片处理失败：「这张图处理不了，换一张试试」，不写任何状态。
  • 存储异常（只读保护）：写入被拦截时明确提示先去「重试保存/读取」，绝不假装成功。
J3

回家批量出片

目标：3 单 3 步以内推进完，不必逐单进详情
  1. 首页「待发片」区（最多 4 条 + 「还有 N 单」）或订单页，按状态看缺口 chips：待提审 / 待正片 / 待副片 / 待发布。
  2. 行尾按钮就是当前唯一该做的动作：提审 → 发副片 → 发正片 → 发布。点一下即完成，列表原地刷新。
  3. 要点开详情时，进度条五节点会按该单配置自动增删（不要求副片的单不出现副片节点）。
  4. 提审后出现「合格 / 不合格」二选一；再点一次可清除。
  5. 正副片出齐后，「发布」按钮才生效。 反馈：每次标记都有 Toast「已标记发副片 ✓」等
异常与边界
  • 跳步点击：未提审就点发片 →「请先完成「提审」再标记「副片发出」」，而不是静默失效。
  • 未出齐点发布：「正片/副片出齐后才能标记发布」。
  • 清除里程碑：确认弹窗列出将被连带清除的下游节点，一次性截断。
  • 超 24h：行内红角标「超24h」，与通知同一口径，不会出现角标有、通知没有。
J4

收款与撤销

目标：2 次点击记完一笔钱，点错能立刻撤回
  1. 入口二选一：收款页行内「标记已收 / 标记到账」，或详情页「收定金 / 收尾款」。
  2. 确认弹层显示店名、大号金额、款项说明（私收 / 约定抖音商单结算）。
  3. 选收款方式芯片（默认：平台单=抖音商单，私收=微信）；渠道仅作记录标签，不做真实支付。
  4. 点「确认收款 ¥X」→ 写流水 + 标记已收时间 + 关闭弹层。 反馈：Toast「已收尾款 ¥1,000 · 微信」+ 右侧「撤销」
  5. 尾款收齐后自动清除该单的催收备忘（已排的通知一并撤销）。
异常与边界
  • 重复收款：「该笔款项已记录，请勿重复收款」。
  • 金额无效：0 元单或金额被改成非法值 →「没有有效的待收金额，不能记账」。
  • 撤销失效：期间订单标记或流水被改过 →「这笔收款已被改动，无法撤销」，不做危险回滚。
  • 撤销入口二：编辑弹层可「撤销定金/尾款记录」，会连同流水一起删除，需二次确认。
J5

逾期催收

目标：不靠记忆，也不把关系催崩
  1. 首页红色告警卡「N 笔尾款逾期 · 待催收 ¥X」→ 点击直达收款页「待催收」筛选。
  2. 收款页按 ≤7 / 8–30 / 30+ 分桶，逾期越久排越前；已设备忘的单落到「已设提醒」。
  3. 打电话/微信问完，点详情「再催一次」→ 选快捷答复（说这周给 / 财务走流程 / 没回复…）或自填 → 记下。
  4. 同时点「1 / 3 / 7 天后提醒」→ 到点生成一次性本地通知；到期前首页不再红催，只留灰标。
  5. 每天 09:00 还有一条汇总通知：仅报「N 笔 · 最长 M 天」，不含金额。 反馈：记录后「已记录第 3 次催收 · 说这周给」
异常与边界
  • 痕迹封顶：只保留最近 50 次，超出提示「最早一条已被挤出」。
  • 备忘过期：提醒响过即视为已用过，不再显示「X 日再催」的过去日期。
  • 结清/改平台单：备忘自动失效并撤销通知，避免半夜为已结清的单弹提醒。
  • 关闭每日提醒：只撤汇总，不动用户自设的 1/3/7 天备忘与 24h 出片提醒。
J6

多账号分账

目标：合看总额、拆看单人，报名资料一键取用
  1. 统计页「我的账号 → + 添加」录入昵称（必填）、手机号、抖音号、头像（相册选图后可拖动缩放裁剪）、标识色（8 档）。
  2. ≥2 个账号后，首页/行程/订单/收款/统计五页顶部出现账号筛选条：全部 / 各账号（选中用该账号色填充）。
  3. 订单列表行首一条 3px 账号色条 + 迷你头像小标，不全行铺底色（避免白卡片里套色块）。
  4. 建单时多选账号 → 一个商家拆成 N 笔独立订单，分别维护进度与收款。
  5. 要去报名时点「拷贝」→ 昵称 + 抖音 + 手机一次拷走。 反馈：「已拷贝「饱饱」资料 ✓」
  6. 历史单未挂账号时，统计页出现「N 笔未指定 → 批量改挂」，一次挂到所选账号。
异常与边界
  • 只有 1 个账号：筛选条、选号卡、账号标签全部不出现，订单自动归属，零打扰。
  • 删除账号：名下订单转为「未指定」，不删单；若正在筛选该账号，筛选自动回到「全部」。
  • 头像移除：必须真正删掉库里的值，不能只清预览。
  • 筛选与分享：分享图只画当前账号的单 —— 别把不打算分享的内容画进去。

8.3 校验规则

金额

  • 必须为非负数，最多两位小数；空字符串在定金字段视为 0。
  • 定金不得大于总价；总价可为 0（纯置换单）。
  • 已存在收款记录时，编辑总价/定金被禁止并给说明。
  • 待收金额为 0 时不允许记该笔款项。

时间

  • 预约时间必须是合法的本地日期时间（回读校验，拒绝 2 月 30 日这类值）。
  • 里程碑时间一律取「现在」，不允许手填（避免伪造时间线）。
  • 预计到账日选日期即可，内部按当天 10:00 存储。
  • 备忘时间固定为「N 天后 09:00」，与每日汇总时间一致。

出片要求

  • 正片/副片至少勾选一项，否则交付线永远无法完成。
  • 改配置后进度条节点即时增减；已标记过但新配置不要求的节点不显示。
  • 「已交付」判定严格按配置，不按「有任意片」。

账号

  • 昵称必填；手机号、抖音号、头像、色号选填。
  • 多账号新建订单必须至少选一个账号；单账号自动归属。
  • 删除账号后，其订单转为「未指定」，可通过批量改挂恢复归属。

9.1 排程与隔离规则

规则说明
id 分段汇总 = base+1；单笔备忘 = base+100000+订单号；出片提醒 = base+300000+订单号。三段互不覆盖，订单号上限 99999 保证不越界。
模式隔离工作数据 base=0，演示数据 base=500000；演示模式不排真实通知（否则演示单会真的弹提醒）。

权限时机只在真的有通知要排时才申请权限，不在首次启动就弹——保存一笔普通订单时弹通知授权会让用户莫名其妙。
失败静默排程失败仅打日志，不阻断业务；App 内角标、列表标红、首页告警卡始终可用。
关闭语义「关闭每日催收提醒」只撤汇总，不动用户自设的备忘与出片提醒 —— 连带取消会让用户明确设置的提醒静默消失。
与「日程线」的边界：本产品不发「明天 10 点去某店拍摄」的预约提醒。 理由是达人本身就以日历/服务商群为主要排期入口，重复推送会削弱通知的可信度； 这里只提醒三类「不做就会有损失」的事：该催的钱、该交的片、用户自己要求记住的跟进。

10.2 存储与一致性

双端持久化

  • iOS 原生：App 沙盒内 SQLite（真实 .db 文件），每次改动即写盘。
  • Web：IndexedDB + localStorage 双副本，按 revision 取新。
  • 两套数据（工作/演示）在同一库内以 mode 隔离，主键为 (mode, id)，互不覆盖。
  • 切后台/关页前排干待写队列 —— 点完「确认收款」立刻杀 App 也不能丢。

异常保护

  • 只读保护：检测到读库异常时进入只读态，所有写动作被拦截并提示，避免覆盖原数据。
  • 替换前备份：导入/清空/恢复前自动留一份快照（仅保留最近一份），可一键撤回或导出。
  • 不确定性提示：备份读取不完整时暂停恢复，引导先导出再处理。

隐私与合规PRIVACY

隐私在这里不是合规成本，而是核心卖点：达人手里最敏感的是「谁家给了多少钱」。

四条硬承诺

  • 不收集：无埋点上报、无崩溃上报、无设备信息采集。
  • 不上传：无服务端、无账号体系；断网可用。
  • 不申请多余权限：相册（选头像/随手拍）、相机（拍摄）、定位（到店记录，可拒绝）、通知（可关闭）。
  • 可彻底删除：清空数据 + 删除 App 即无残留；也提供导出后再清空的标准路径。

产品内的隐私设计

  • 隐私模式：顶栏眼睛一键隐藏全站金额，用于当面给对方看屏幕或录屏。
  • 分享图不含金额：对外分享物天然脱敏，避免「发给搭档结果泄露报价」。
  • 通知不含金额：锁屏可见区域只有条数与天数。
  • 定位只存坐标：不反查地址、不上传；仅用于「看位置 / 导航」。

12.2 六条体验原则（后续迭代的判定尺）

① 一屏一决策

首页只回答「今天拍什么」和「谁欠我钱」。新信息要么进告警卡，要么进速览格，不许无限堆区块。

② 高频动作 ≤2 tap

能在行内做的绝不放详情页。打卡、提审、发片、收款全部行内可达。

③ 录单零键盘

能默认就默认、能点选就点选（服务商芯片、账号卡、相对日标签）；次要字段可空。

④ 状态尽量自动推进

拍照即「已拍摄」；收款即清备忘；结清即退出催收池。少让用户维护状态。

⑤ 钱必须可逆

任何一键记账都要有一步撤销；撤销不成立时明确说明原因，不做静默回滚。

⑥ 信息随手能拿走

地址能导航、账号资料能拷贝、账单能导出、行程能分享 —— 数据不属于 App。

  • 新建：只填商家 + 总价能保存；定金 > 总价被拦；正副片都不勾被拦；多账号不选被拦。
  • 冲突：同日 ±2h 出现横幅并列出时间/店名/地点；不阻止保存；换日期后横幅实时更新。
  • 拍摄：打卡写时间；随手拍同时写图与时间；GPS 失败不影响状态；金额格出现底图。
  • 推进：跳步点击有提示；未出齐不能发布；清除上游会连带清下游并确认。
  • 提醒：拍摄 +24h 出片通知到达；出齐后通知消失；1/3/7 天备忘到点提醒；关闭汇总不动单笔备忘。
  • 收款：记一笔后金额、统计、流水三处同步；Toast 可撤销；重复收款被拦；已有收款后总价锁定。
  • 催收：痕迹按时间倒序、最近 4 条、超 50 条提示；设备忘后首页转琥珀、到期前不再红。
  • 多账号：1 个账号时无筛选条；≥2 时五页筛选生效且角标随筛选变；删号后订单转未指定。
  • 数据：CSV/JSON/.db 三种导出均成功（原生走分享面板）；JSON 导入校验失败有明确原因；清空后可恢复。
  • 体验：弹层可下拉关闭；表单只从头部拖；双击不缩放；长按不弹气泡；保存条常驻。
  • 隐私：眼睛一按全站金额隐藏；隐藏态编辑金额只读并给说明；分享图不含金额。
