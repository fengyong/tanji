# 探记云端版产品需求规格

- 文档版本：v0.1，2026-11-21。
- 状态：需求与设计基线，供评审；不是已实现功能说明。
- 开发隔离：`feat/cloud-local-first`，独立 worktree `tanji-cloud`，基于 `main@aaf57d9`。
- 技术与分期：[云端技术架构与实施计划](cloud-architecture.md)。

## 1. 产品意图

这不是把本机记账页面搬到服务器，而是保留随手记录、离线能用的体验，让云端提供数据归属、恢复、同步和受控协作。

用户每天关心三个问题：我的安排有没有记住、我的钱有没有算对、搭档知不知道何时去哪里。系统不能把网络状况、数据库差异或同步冲突的处理成本转嫁给日常操作。

核心原则：

1. 本地先保存，网络不阻塞记账；只有本地事务成功才能显示“已保存”。
2. “已保存在本机”和“云端已确认”是不同状态，必须如实展示。
3. 云端确认过的数据可用于换设备恢复；从未上传的数据不能声称已云备份。
4. 一个账号拥有自己的账本；协作通过另一个独立账号授权完成，不共享账号密码。
5. 搭档只拿到完成赴约所需的信息，财务及其他订单明细根本不下发。
6. 同步异常不能静默丢失修改、重复入账、复活删除记录或扩大共享范围。

## 2. 要求来源与本次决策

### 2.1 用户已明确的要求

| 编号 | 要求 |
| --- | --- |
| U01 | 独立分支/worktree 开发，不干扰现有本机版与原生版 |
| U02 | 支持注册、登录，数据保存到云端 |
| U03 | 客户端使用 SQLite，后端使用 Go，云端数据库使用 MySQL |
| U04 | 平时本地读取和修改，支持离线读取与编辑，联网后自动双向同步 |
| U05 | 网络可用时，修改立即尝试上传，不要求手动备份才保存到云端 |
| U06 | 搭档支持注册账号与非账号两种类型；真实账号能看到分配给自己的计划 |
| U07 | 搭档或额外受邀账号只看档期与地址，不能改，也不能看其他明细 |
| U08 | 同一账号只允许一个有效登录，新登录使旧登录失效 |
| U09 | 后续原生 APP 支持选择店铺地址/地图地点 |
| U10 | 借鉴 Binlog 的记录变化与重放原理，而非操作、复制数据库 Binlog |

### 2.2 本次由设计方作出的决定

这些是根据产品意图确定的执行基线，不冒充用户逐项指定的要求。

- 第一版注册采用邮箱和密码，邮箱验证码用于验证及找回；不把“真实账号”解释为身份证实名。
- 第一版每个订单一名主要搭档，可另加多名只读查看者；不做团队共同编辑。
- 注册搭档须经邀请接受建立联系，再对具体订单明确共享；名字相同不自动关联账号。
- 共享白名单包含发布者昵称、店名、预约时间、地址、地图坐标与必要的改期/取消状态；不包含实际拍摄/交付状态。
- 先交付云端 PWA，再用共享业务与同步模块接入现有 Capacitor 原生路线，不另做一套 Swift 业务系统。
- 地点第一版可手填，后续原生地图优先接高德；地图不可用不能阻塞保存。
- 已知会话失效后锁定本机工作区；未知失效的离线设备可继续记录，联网先核验身份，旧队列不能直接上传。
- 本人已有本机身份的离线工作不设置强制按天停用；首次登录、主动退出后重新登录、邀请接受、账号安全操作必须联网。
- 为降低长期共享缓存暴露，搭档缓存超过连续 7 天未验证权限后在正常界面隐藏，联网验证后恢复；这是客户端约束，不承诺抵御设备持有者读取底层文件。
- 云端不采用整库覆盖，也不承诺任意设备可同时编辑同一账号数据。

## 3. 范围

### 3.1 第一版必须包含

注册/验证/登录/退出/找回密码；单有效会话；本人订单、收款、设置的本地优先存储；待同步队列、上传去重、增量下行、冲突保留、删除同步；真实与外部搭档；按订单的只读共享；手填地址；同步状态页；旧数据迁移和导出；服务端备份与恢复演练。

现有双轨工作/资金状态、催收、统计、隐私显示和指定日期分享图片继续保留。图片分享是一次性图片，不等于可撤销的账号授权。

### 3.2 后续阶段

原生 SQLite 适配、原生会话安全存储、地图 POI 选点、系统导航、原生生命周期同步；设备能力允许时的后台补同步与通知。

### 3.3 明确不做

多人共同改账、匿名公开档期链接、完整 CRM、聊天、在线收款/支付、银行卡对接、分账、实时位置跟踪、地图离线包、自建地图数据、微服务/Kafka 集群、通用数据库复制平台、端到端加密承诺。

## 4. 角色与权限

同一注册账号可以是自己账本的主人，也可以是别人的搭档；角色是相对于数据所有者而言，不是全局管理员角色。

| 操作/信息 | 本人 | 已授权账号搭档 | 已授权查看者 | 外部搭档/未授权账号 |
| --- | --- | --- | --- | --- |
| 自己订单完整内容、收款、统计 | 可读写 | 不可见 | 不可见 | 不可见 |
| 被明确共享的档期白名单 | 可读写源记录 | 只读 | 只读 | 不可见 |
| 其他订单、未分配日期的安排 | 可见自己的 | 不可见 | 不可见 | 不可见 |
| 联系人、电话、渠道、备注、其他搭档身份 | 本人可见 | 不可见 | 不可见 | 不可见 |
| 授权、更换搭档、撤销分享 | 本人可操作 | 不可操作 | 不可操作 | 不可操作 |
| 将收到的共享记录写回源订单 | 不适用 | 禁止 | 禁止 | 禁止 |
| 导出完整账本 | 本人可以 | 禁止他人账本 | 禁止他人账本 | 禁止 |

接收者主动保存截图无法禁止，分享前告知发布者。接收者转发截图不使第三人获得在线查询权限。

## 5. 功能需求

### FR-01 注册与账号安全

- 注册填写邮箱、密码、昵称；验证邮箱后激活账号。昵称可重复，用户 ID 不可重复。
- 密码最少 12 字符，允许密码管理器及长口令；不要求机械组合大写/符号，不截断口令。
- 找回通过验证邮箱完成；验证码短时有效、单次消费、限制尝试次数与发送频率。
- 登录、找回和账号查询不得泄露某邮箱是否注册；同一业务流程返回统一提示。
- 修改密码、重置密码、停用账号均使此前会话失效。
- 账号停用/删除须联网、再次认证、明确确认；处理自己发出的共享、云端数据保留及备份到期清理，不假装能立即擦除离线设备。

### FR-02 单点登录与换设备

- “一处”定义为一个浏览器资料/原生安装产生的有效会话；浏览器与 APP 算不同终端。
- 同一浏览器标签页共享会话，但只允许一个运行中的账本实例，其他页提示返回原页面，避免同时打开 SQLite。
- 新设备成功登录后替换旧会话。登录成功的原子边界后，旧会话不能提交新的写操作；已经完成的旧事务不撤销。
- 在线旧设备通过通知或下一次请求发现失效后立即遮蔽业务界面，停止同步；断网或系统挂起时不保证即时显示锁屏。
- 旧设备未上传修改进入“待恢复”，不丢弃、不自动迁入新账号。由同一所有者联网重新认证后核对云端，确认恢复或导出。
- 重新登录旧设备同样会使新设备会话失效，界面须事先说明，不能暗中轮流抢占。
- 主动退出默认清理可清理的本机缓存；如有未同步数据，先提供同步、导出、取消退出或明确丢弃选项。离线退出立即锁定本机，云端会话撤销只能待联网完成；若清除了令牌，云端会话还会在过期或下次新登录时失效。

### FR-03 本地工作区

- 浏览器/APP 已初始化且曾成功登录后，可离线查看与编辑本人数据。
- 每个账号、环境和演示集分别隔离数据库、待同步队列和同步游标；切换账号不复用上一账号队列。
- 演示数据永不自动上传，不自动邀请搭档，不与工作账本混存。
- 创建订单、改期、标记里程碑、记收款、撤销错误收款、填写地址均先提交本地事务。
- 事务失败则明确提示“未保存”，保留表单可重试；不得先显示成功再默默失败。
- 离线查看别人共享的档期只使用曾合法下载的最小信息，不支持离线首次查询账号/接受邀请。
- 浏览器存储被系统清理后，只能恢复云端已确认的数据；未同步内容的风险通过状态与备份提醒告知。

### FR-04 自动同步及状态

触发时机：本地事务成功后、应用进入前台、重新联网、登录验证成功、收到服务端变化提示、用户手动重试。网络标志只是触发信号，请求成功才说明链路可用。

| 状态 | 用户含义 | 处理 |
| --- | --- | --- |
| 已保存本机，待同步 N 项 | 本机已落盘，云端未确认 | 正常离线工作，不宣称完成云备份 |
| 正在同步 | 正在验证/上传/拉取 | 可继续本地录入，使用独立队列串行处理 |
| 已同步，最后确认时间 | 当前已知本机变更均获确认，且完成一轮下行 | 不是永不丢失或永久一致的承诺 |
| 网络不可用/服务繁忙 | 可重试的传输失败 | 自动退避重试，保留队列 |
| 有冲突/数据需修正 | 云端拒绝当前业务变更 | 保留本地与云端版本，引导处理 |
| 登录已失效 | 不能继续上传/下载 | 锁定内容，保留待恢复数据 |
| 存储失败 | 本机未可靠保存 | 显著提示，不推进同步队列 |

恢复网络时先核验会话，再对账已有结果、拉取变化、处理可上传队列、再次拉取；不以本机时钟判断哪个设备的内容“更新”。

### FR-05 订单、金额和收款

- 保留预约、拍摄、提审、短/长片、催收等工作流；离线更改后，搭档在云端确认前仍只能看到上次确认的档期。
- 金额按人民币“分”的整数保存和传输，定金不超过总价；零元单无需生成零金额流水。
- 收款仍只是记账，不触发实际支付。
- 收款记录有稳定 ID。重复点击、请求重试、响应丢失不能产生重复账。
- 已确认的收款采用保留原记录＋明确撤销记录的方式纠错；撤销不是退款，也不是删除历史。
- 有有效收款时禁止直接改总价/定金；须按业务规则先撤销错误流水，避免历史金额被改写。
- 统计根据有效收款计算，必须避免将撤销动作算成新的实际付款。
- 资金线与工作线独立；缺定金不能隐藏已拍摄订单的逾期尾款，平台结算免催收沿用现规则。
- 有有效流水的订单只能归档，不能通过删除订单抹掉实际收款；误记须先明确撤销。归档不剔除真实收款统计，无有效流水的订单可逻辑删除。
- 第一版沿用整笔定金/整笔尾款，不扩展分期、部分付款或退款账务。

### FR-06 搭档与邀请

- 选择框区分“已关联账号”“外部搭档”；外部搭档保存名字，不搜索或猜测同名注册者。
- 使用不可枚举的邀请凭据或精确账号标识建立联系，展示昵称/账号标识供确认，不开放全站账号通讯录。
- 邀请接受后成为可选择的账号搭档；建立联系本身不共享整个账本或历史订单。
- 本人给订单选中已关联账号并确认共享后，该账号获得此订单的最小档期视图。
- 第一版每单一名主要搭档；额外查看者通过独立只读授权添加，同样需要已接受的联系关系。
- 离线可选择已缓存的已关联搭档，但显示“共享待同步”；服务端发现关系已撤销时拒绝授权，不能因此丢掉本人的订单修改。
- 外部搭档以后关联账号须显式选择，列出要补发的订单再确认，不自动共享全部历史。

### FR-07 搭档计划页

- 接收者在“共享给我的”入口按今日、明日、日期查看已授权档期，与自己的订单明确区分。
- 可显示：发布者昵称、店名、预约开始时间、可选结束时间、时区、地址、地图位置、改期/取消提示及同步时间。
- 不显示：订单总价/定金/尾款、收款渠道、流水、客户联系人、电话、内部备注、业务渠道、拍摄/交付进度、其他查看者列表、所有者统计。
- API、同步包、SQLite 共享表、搜索、导出、通知文案都必须遵守同一白名单；不能只依赖界面隐藏。
- 已授权档期可以看历史，不存在“选择一个搭档就能看这个人的所有明天安排”的隐式权限。
- 接收者不能编辑源档期、标记拍摄或收款，也不能替所有者授权第三人。

### FR-08 改期、取消和撤销权限

- 改期更新同一共享记录，接收者不产生重复行程。
- “取消预约”是业务状态，已有授权接收者看到取消提示；“删除订单/撤销共享”是删除或权限变化，接收者收到移除事件。
- 更换主要搭档后，旧搭档的主要搭档授权撤销。若此人还被单独添加为查看者，界面须明确提示该人仍能查看，并提供撤销全部权限入口。
- 撤销尚未获云端确认时，不能显示“对方已不可见”。
- 在线 API 在撤销事务提交后的新请求中拒绝访问；离线接收者缓存只能在再次联网时清除，不能保证远程即时擦除。
- 缓存清除覆盖共享表、搜索索引、内存及应用内通知；不影响接收者自己的账本。

### FR-09 地点与导航

- 第一期：店名、地址文本；可保存经纬度、POI ID、地点来源和坐标系，缺坐标也可完成订单。
- 地址是订单的历史快照，不因地图平台后来更改店名而自动改写旧订单。
- 第二期原生 APP：搜索 POI 或选点、预览并确认地址，保存后可调用已安装地图导航。
- 默认不申请持续定位；“使用当前位置”时才申请一次性授权，拒绝授权不影响手填地址或搜索地点。
- 国内高德坐标明确标记 GCJ-02，不能冒充 WGS-84；切换地图时做有依据的转换或保留源坐标。
- 保存地点不等于缓存完整地图；网络差时展示已保存地址，地图加载失败不阻塞记账。

### FR-10 迁移、恢复与数据导出

- 迁移前生成可验证备份，预览订单数、有效流水数、金额汇总、异常项及目标账号。
- 只有明确确认后才把旧工作数据绑定到当前账号；演示数据不得随首次登录自动上云。
- 旧整数订单 ID、无稳定 ID 的流水映射为稳定全局 ID，迁移映射保留，重复导入同一来源不能重复入账。
- 旧搭档文本按外部搭档迁移，缺地址保持空，不猜测真实账号或地点。
- 云端已有数据时，第一版只支持预览后增量导入/去重；不提供无提示的整库覆盖或一键把云端替换成本机旧备份。
- 初次同步、全量重建、会话恢复均保留未上传操作；失败不能清空本机账本。
- 完整导出仅针对自己的账本；共享给自己的档期不会被当作自己的完整订单导出。

## 6. 不可消除的边界

1. 断网设备无法即时接收踢出、改期、撤销授权；前台联网后才能核验。
2. 截图、手工复制与设备持有者自行提取的数据无法远程收回。
3. 浏览器/APP 被系统挂起或杀死，不能保证持续实时同步；主保证是前台与恢复前台同步。
4. 已保存本机但未上传的数据，在卸载、清理或设备损坏时可能丢失。
5. 客户端账号隔离不是对共享操作系统用户、已解锁设备或恶意开发者工具的强加密隔离；不承诺端到端加密。
6. 客户端 SQLite 与 MySQL 不要求表结构逐字一致；共享的是业务语义和协议，不是数据库内部文件。

## 7. 验收指标

以下是实施后的验收目标，不是当前已验证的性能结果。

- 基准规模：单账号 10,000 笔订单、30,000 条收款/撤销记录；单订单最多 20 个接收账号，超过时明确提示。
- 本地常见保存 P95 不超过 200 ms，不包含用户输入和首开数据库时间；在约定中端真机记录测量结果。
- 前台正常网络（往返不超过 200 ms、无故障注入）下，本地提交后 1 秒内发起上传，5 秒内通常收到云端确认。
- 搭档前台在线时变更提示通常 5 秒内到达；提示通道不可用时 30 秒轮询补偿。均不作为断网或后台保证。
- 同步同一操作重试 100 次只产生一次业务效果；崩溃恢复不出现只有业务数据而无待同步记录的半事务。
- 所有越权接口、历史同步页、全量快照和推送不得返回禁止字段；以实际响应和本地库检查验收。

## 8. 关键验收场景

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| AC01 | 断网新建、改期、记收款，强制退出后重开 | 已成功提交本地的数据和待同步操作仍在 |
| AC02 | 服务端已提交，客户端未收到响应，再次上传 | 仅记一次账，返回原操作结果 |
| AC03 | 连续离线新建→改价→收款，随后联网 | 顺序与依赖正确，不因本机版本不同误冲突 |
| AC04 | 下行到来时本机已有未上传修改 | 不覆盖本地修改；有冲突则保留双方并提示 |
| AC05 | 同步一页中途崩溃 | 数据与游标一起提交或一起回滚，不跳过事件 |
| AC06 | A 登录后 B 以同账号登录 | A 后续请求拒绝；在线锁定，离线修改不自动回灌 |
| AC07 | A 账号退出，B 账号在同设备进入 | B 的界面/请求/队列不包含 A 的数据 |
| AC08 | 选注册搭档后搭档查看明天 | 只看到明确分配的店名、时间、地址等白名单 |
| AC09 | 搭档改请求参数访问财务或他人订单 | 服务端拒绝，不泄露字段或对象是否存在 |
| AC10 | 外部搭档与某注册账号同名 | 不自动绑定，不自动共享 |
| AC11 | 改期、更换搭档、撤销共享 | 新接收者收到正确档期，旧接收者恢复联网后移除缓存 |
| AC12 | 服务端先处理撤销，接收者再拉历史同步页 | 不能从历史数据重新拿到已撤销内容 |
| AC13 | 删除记录后旧设备带着旧修改回来 | 不复活删除记录，进入已删除冲突处理 |
| AC14 | 游标过期需全量重建，本机仍有待同步队列 | 重建后队列仍在，逐项对账而非覆盖 |
| AC15 | 迁移同一旧备份两次 | 不重复创建订单、不重复记账 |
| AC16 | 磁盘配额耗尽或数据库初始化失败 | 不显示保存成功，不自动删除旧数据库 |
| AC17 | 地图拒绝定位/不可用 | 可以手填地址、正常保存和同步 |
| AC18 | 服务端备份恢复到较早时间 | 同步重新对账，不误报成功或重复收款；旧会话全部失效，恢复出的共享默认冻结，不能把撤销过的权限重新开放 |
