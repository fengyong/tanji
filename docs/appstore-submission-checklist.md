# 探记 · 正式上架 App Store 的难点清单

> 2026-11-28 基于 ASC API 实测 + 本机代码扫描整理。
> 每一项都标了**是否阻塞提交**、**谁来解**、**依据**。
> 目的不是罗列，而是让你一眼看出「今天到底能不能点提交」。

---

## 一、结论速览

**现在点「提交以供审核」会被直接拒绝**，缺 9 项。但真正的难点**不在填表**，
而在下面这三类：

| 类型 | 难点 | 性质 |
|---|---|---|
| **A. 硬阻塞** | 不补就提不了审 | 机械工作，1-2 小时 |
| **B. 审核风险** | 可能被拒，或被要求改代码 | **需要决策，有返工风险** |
| **C. 隐性门槛** | 容易忘，且不报错 | **最容易被卡住的地方** |

**A 类**：描述/副标题/关键词、截图、审核联系信息、定价、上架可用性、年龄分级问卷
**B 类**：真机验收未做（Face ID / 通知 / 导入导出）、描述与实现必须严格一致
**C 类**：**中国区 App 备案**、税务与银行信息、买断制且无演示账号的审核沟通、TestFlight 构建 90 天有效期

## 一.5、三个最重要的判断（如果只看三行，看这里）

**① 技术上离上架只差填表 + 一次真机验收。**
代码侧已经过实测：无网络请求、无内购、无账号、权限声明与实现一一对应、
隐私清单完整、法律页公网可访问。**没有需要改代码的架构问题。**

**② 中国区备案对探记有明确解法，不用等。**
探记是**纯单机零网络 App**，正好落在 Apple 的**备案豁免**范围内
（3 个工作日，走 ASC 客服通道上传 PDF 声明）。
即使不申请豁免，**提审本身也不校验备案号** ——
可以先只开美国区上线，备案并行推进，不卡发布节奏。

**③ 唯一真正的返工风险是「真机验收没做」。**
Face ID、通知提醒、导出导入这四项**模拟器根本测不出来**，
而审核员会逐项点。没做完就提审，大概率吃 2.2「功能不完整」，
还得改代码 + 重传 + 重排期。**这是最该优先投入的一件事。**

## 二、A 类 · 硬阻塞（不补无法提交）

### A1. 文案全空 —— 8 个字段一个都没填

**版本级**（`GET /v1/appStoreVersionLocalizations/c7c24edd-…`，zh-Hans）：

```
description       = null   ← 完整描述
keywords          = null   ← 关键词，≤100 字符，逗号分隔
promotionalText   = null   ← 宣传文本，可留空但建议写
supportUrl        = null   ← 支持页，审核员会点开，404 直接拒
marketingUrl      = null   ← 营销页，可留空
```

**App 元信息级**（`GET /v1/appInfos/c7681246-…/appInfoLocalizations`，zh-Hans）：

```
name              = 探记   ← 已填
subtitle          = null   ← 副标题，≤30 字符
privacyPolicyUrl  = null   ← 隐私政策链接（公网页面已可访问，但 ASC 里没登记）
privacyPolicyText = null
```

> 📌 `copyright` **已填** `2026 探记`，在版本资源上
> （`GET /v1/appStoreVersions/7e8012d1-…` 实测 `copyright=2026 探记`）。
>
> 📌 **字段归属容易踩坑**（2026-11-28 实测确认）：
> `supportUrl` / `marketingUrl` 挂在 **appStoreVersionLocalizations** 上，
> **不在 `appInfos` 上**——用 `fields[appInfos]=supportUrl` 会被 Apple 拒绝：
> `'supportUrl' is not a valid field name`。
> 同理 `name` / `subtitle` / `privacyPolicyUrl` 在 **appInfoLocalizations**，
> 不在版本级资源上。填之前先看对资源，否则会找不到字段。

### A2. App 截图 —— 0 张

```
GET /v1/appStoreVersionLocalizations/c7c24edd-…/appScreenshotSets → 0 条
```

这是**最花时间**的一项：
- 至少要 **6.9" iPhone** 尺寸（`1242×2688` 或 `1290×2796`），
  可选 6.7" / 6.5" / 5.5"，**不上传 iPad 尺寸可以**（iPad 截图非强制）
- 每种尺寸至少 1 张，最多 10 张
- **必须是真机截图**，不能用设计稿
- **纯 API 上传很繁琐**（要先建 `appScreenshotSets`，再按尺寸建
  `appScreenshotSets/{id}/appScreenshots` 并上传二进制），
  **强烈建议走 ASC 网页端拖拽**

> ⚠️ 截图要展示真实内容。如果 App 是空数据状态截的图，
> 审核员点进去发现「什么都没有」会怀疑是个空壳 App。
> **建议先造几笔演示订单再截图**。

### A3. 审核联系信息 —— 为空

```
GET /v1/appStoreVersions/7e8012d1-…/appStoreReviewDetail → data: null
```

需要填：姓名、电话、邮箱，以及**审核员联系方式**（可与本人相同）。

### A4. 定价 —— 当前是 0 元（免费）

```
GET /v1/appPriceSchedules/6840332432/manualPrices → 404（无手动定价）
```

**这是产品决策项，需要你定价格。**
- 买断制 App 可以直接标价（一次性购买，无 IAP）
- `baseTerritory` 当前是 **USA**，定价界面是美元
- ⚠️ **手动定价必须逐个地区确认**。中国大陆区要单独设价，
  否则中国区显示的是换算价或不可用

### A5. 上架可用性 —— 未创建

```
GET /v1/apps/6840332432/appAvailabilityV2 → 404
```

要选可售地区。**中国区有额外前置（见 C1）**。

### A6. 年龄分级问卷 —— 32 项里 29 项未作答

```
GET /v1/appInfos/c7681246-…/ageRatingDeclaration
→ 未作答 29 / 32
```

大部分项对本 App 都是 NO（无广告、无赌博、无成人内容、无 UGC、无社交…），
但有几项需要你确认，因为**本 App 的业务性质容易踩**：

| 问项 | 探记的实际情况 | 建议 |
|---|---|---|
| `messagingAndChat` | 无聊天功能 | NO |
| `userGeneratedContent` | 无 UGC（数据只在本机） | NO |
| `unrestrictedWebAccess` | 无网络请求 | NO |
| `healthOrWellnessTopics` | 无 | NO |
| `datingAndRelationships` | 无 | NO |
| `contests` | 无 | NO |
| `kidsAgeBand` | 面向成年人创作者 | 不选儿童 |
| `profanityOrCrudeHumor` | 无 | NO |
| `alcoholTobaccoOrDrugUseOrReferences` | ⚠️ 探店场景可能涉及酒类商家名 | **要如实判断** |

> 📌 目标分级 4+。但探记是**记账/收款**类工具，
> 里面会出现「催收」「欠款」「尾款」这类词，
> 如果描述里或截图里出现敏感财务措辞，Apple 不会因此提高分级，
> 但**描述用词要克制**。

## 三、B 类 · 审核风险（可能被拒或返工）

### B1. ⭐ 真机验收完全没做 —— 最大的风险

现在**只验证了「装得上、启得来、数据能导入」**，
真正的功能一条没验。审核员会逐项点，而以下几项在模拟器里根本测不出来：

| 功能 | 为什么模拟器测不了 | 失败后果 |
|---|---|---|
| **Face ID 隐藏金额** | `LAContext` 需要真机生物识别 | 直接 2.3 / 2.1 拒审 |
| **通知权限 + 每日催收提醒排程** | 模拟器收不到本地通知 | 审核员看不到提醒 → 判功能不完整 |
| **相册选头像** | `PhotosPicker` 真实相册 | 同上 |
| **导出 JSON/CSV/.db 到「文件」App** | 涉及真实沙盒 + 系统文件共享 | 同上 |
| **导入备份（含恢复点）** | 涉及文件选择器 | 同上 |
| **后台 15 分钟 / 强杀重开数据仍在** | 生命周期 | 同上 |

> 📌 runbook §4 有完整清单，但**一条都没打勾**。
> 这份清单没走完就提审，审核员大概率给 2.2「功能不完整」打回，
> 还得改代码 + 重新上传 + 重新排期。

### B2. 描述必须与实现严格一致

这是**已经踩过一次**的坑，值得单列：

原生版**没有**「打卡记录当前地址」功能（`CLLocationManager` 零依赖），
定位权限声明也已删除。但**混合版有**。
如果描述里写了「自动记录到店定位」，审核员会：
1. 找不到入口 → 2.1「元数据不准确」打回，或
2. 更糟：要求补上这个功能

**写描述的硬规则**：只写当前版本真实存在的功能。
可写的：订单/流水/行程/统计/导出导入/通知提醒/Face ID/账号管理。
**不可写**：GPS 打卡、地图导航、云同步、多设备、团队协作。

### B3. 「无账号、无服务器、无网络」的审核沟通

本 App 的**技术优势**（零网络请求、零数据收集、零第三方 SDK）
在审核时**反而要主动说明**，否则审核员点开发现没有登录页，
可能误判为「功能不完整」。

建议在 `reviewNotes` 里写清楚：
- 不需要演示账号
- 所有数据仅存本机沙盒
- 无网络请求（可对照隐私清单与代码）

## 四、C 类 · 隐性门槛（最容易忘，且不报错）

### C1. ⭐⭐ 中国区 App 备案 —— 有解法，但要选路线

**中国大陆区上架需要 App 备案（工信部）。** 2023-08 工信部《关于开展移动互联网应用程序备案工作的通知》，
App Store 从 2024-04 起对国区强校验。

**但探记的情况很特殊，有两条路可选：**

#### 路线 A · 纯单机豁免（⭐ 探记天然符合，强烈推荐）

判定规则一句话：**发中国大陆 + 有联网 = 必须 ICP 备案；纯单机走豁免；只发海外分区不用备案。**

探记完全符合豁免条件：
- ✅ **全程无任何网络请求**（已实测：代码扫描 `URLSession`/`URLRequest`/`http://`/`https://` **零命中**）
- ✅ 无埋点、无广告 SDK、无第三方 SDK
- ✅ 无云端校验、无内购校验（`StoreKit` 零命中）
- ✅ 数据 100% 存本机沙盒

**操作步骤**：
1. 下载苹果官方**豁免声明模板**
2. 填写 Team ID（`YC9UFHH73D`）、App ID（`com.ord.tanji.app`）、Bundle ID、开发者主体信息
3. **个人手写签名**（企业需法人签字盖章）
4. 通过 **App Store Connect 客服通道**上传 PDF，清晰写明「App 全程无境内网络接入」
5. **审核周期约 3 个工作日**，通过后后台无需填写备案号即可正常上架国区

> ⚠️ **红线**：只要有启动页埋点、加载广告、调用一次云端接口，
> 虚假申请豁免一经核查 → **App 立即下架 + 开发者账号风控标记**。
> 探记当前无网络，**但以后加任何联网能力（如崩溃上报、云同步）都必须重新评估**。

#### 路线 B · 走正式备案（周期 2-3 周）

若将来加了联网能力（或不想走豁免）：
- 通过云厂商（阿里云/腾讯云）提交，向属地省通信管理局办理
- **名称三处必须一致**：备案名 = 图标显示名 = 中国区商店名（= 「探记」）
- 需从 **Apple Distribution 证书**提取公钥 + MD5 指纹
  ```bash
  openssl x509 -inform der -in distribution.cer -noout -fingerprint -md5
  openssl x509 -inform der -in distribution.cer -noout -modulus
  ```
- 管局审核 **3-15 个工作日**，整体按 **2-3 周**预留
- 备案号格式 `京ICP备2026xxxxxx号-3A`（末尾带 **A**，网站备案号末尾纯数字，**不能混用**）
- ⚠️ **必须在 App「设置 → 关于我们」页面静态公示备案号**，
  苹果审核员会真机抽查，未公示会二次驳回

#### ⚠️ 但请注意：提审本身不校验备案号

Apple 官方教程明确指出：**提审不校验备案号**，无备案的新 App 提交审核**能正常通过**，
只是**在中国大陆店面搜不到**（老 App 发新版本后也可能在中国区「静默消失」）。

**所以实用策略是：**
> **先只开美国区（或海外区）提审上线，把产品跑通、把收入通道打通；
> 国区备案并行推进，号码下来后随下一个版本补上即可。**
> 这样不会因为 2-3 周的备案周期卡住整个发布节奏。

**自查国区是否已展示**：
```bash
curl "https://itunes.apple.com/lookup?id=6840332432&country=cn"
# resultCount 为 0 → 中国区店面没展示你的 App
```

#### 📌 行动建议

**第一件事**（5 分钟，只在网页端查）：
ASC → 探记 → **App 信息** → 找「中国大陆 ICP 备案」区域，看是否已备案 / 有无「待确认」提示。

- 若已有备案号 → 无需豁免，走路线 B 的回填流程
- 若没有 → **选路线 A（豁免）**，因为探记是纯单机 App，3 个工作日就能搞定
- 若不确定「是否真的零联网」→ 用路线 A 前先再审一遍代码（当前实测零命中，可用）

> ⚠️ **主体匹配的硬性要求**：备案主办单位必须与开发者账号实名主体一致。
> 个人账号可做**非经营性备案**；若将来要加付费/电商/UGC，**个人主体会被限制**，
> 届时需企业营业执照。

### C2. ⭐ 税务信息 + 银行账号 —— 不填则价格不生效

买断制 App 要真正能卖钱、且中国区能显示正确价格，ASC 里必须先完成：
- **税务信息**（Tax Information）：中国大陆个人/企业
- **银行账号**（Banking Information）

**这两个填完，App Store 才能真正接受付款。**
不填的话，App 可能「能上架但卖不了」——审核能过，上线后 0 收入。

> 📌 同样**只能在网页端填**，API 无覆盖。

### C3. 买断制 + 无 IAP 的合规性

- ✅ **没有内购**是对的，Apple 允许工具类 App 一次性买断
- ⚠️ 但如果描述里暗示「订阅解锁更多功能」→ **必须改成 IAP**，否则 3.1.1 拒审
- ⚠️ 如果以后加「云同步 / 多设备 / 团队版」这类**数字服务**，
  那部分**必须走 IAP**（这是最容易被忽视的未来雷）

### C4. TestFlight 构建 90 天有效期

- 当前构建 `20261128.212041` 的 `expirationDate = 2027-02-26`
- **过期后该构建不能再用**，提审前需重新上传
- 如果你打算拖到明年才提审，**现在这版构建会作废**

### C5. 已装机的开发签名包 ≠ 可上架包

直装给杨小姐的是**开发签名**（`Apple Development`，2027-11 到期），
**不能提交审核**。提审必须用 **App Store 分发签名**的构建。
本轮已有 `探记 App Store` 描述文件（`get-task-allow=false`），随时可出正式包。

### C6. 出口合规每次新构建都要重答

已声明过的那次只对 `20261128.212041` 生效。
**重新出包上传后必须再 `PATCH /v1/builds/{id}` 声明一次**，
否则又会出现「Build is not in an externally assignable state」。

## 五、建议的执行顺序

### 阶段 1 · 今天能做完（约 2-4 小时）

1. **查中国区备案状态**（ASC → App 信息 → 中国大陆 ICP 备案），没有就走豁免

3. 定价格（含中国区），写文案（描述/副标题/关键词/宣传文本/supportUrl）

5. 填审核联系信息
6. 答年龄分级问卷
7. **真机验收清单全走一遍**（runbook §4）← 不要跳过

### 阶段 1.5 · 上架范围策略（建议）

**先只勾选美国区（或海外区）提审**，理由：
- 绕开国区备案的 2-3 周周期，不卡发布
- 顺带验证一遍「提审 → 审核 → 上架 → 收款」全流程
- 备案号下来后，随**下一个版本**补上并勾选中国区

> 📌 前提：税务 + 银行信息必须先填好，
> 否则美国区也无法真正收款（App 能上架但卖不了）。

### 阶段 2 · 出正式包并提交

```bash
# 出 App Store 签名包（开发签名包不能提审）

  '{"data":{"type":"appStoreVersions","id":"7e8012d1-2117-4cac-9c97-fda593536ff2",
```

### 阶段 3 · 提交

- ASC 网页端 → 探记 → App Store → 版本 1.0.0 → 「添加以供审核」
- 选构建 + 填描述 + 提交

## 六、一句话总结

**技术上离上架只差填表；真正的难点是三件事：**
1. **真机验收**（Face ID / 通知 / 导入导出，模拟器测不出来，不做完必被打回）——**优先级最高**
2. **中国区 App 备案**（探记符合豁免条件，3 个工作日；且提审不校验，可先上美国区）
3. **税务 + 银行信息**（不填则卖不了钱，且不会报错）
