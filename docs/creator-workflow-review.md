# 达人工作流与交互评估(v0.6 · 2026-11-22)

> 目的:把 App 放回达人的真实工作节奏里,回答"现在的交互方不方便、够不够用"。
> 本文只谈**功能与流程**,不谈视觉。视觉探索的产物归档在 `docs/design-preview/`,落地顺序排在功能之后。
> 所有结论以当前代码为准(`www/index.html` / `www/logic.js`),文中行号可直接 `grep -n` 复核。

---

## 0. 一句话结论

主线(排期 → 拍摄 → 提审 → 出片 → 发布 → 收款 → 催收)**已经闭环**,而且"下一步该做什么"有引导(详情页永远只推一个主按钮)。
真正的摩擦不在数据,而在三条取数/取操作的路径上:

1. **录单要滚两屏**——接单发生在微信里,30 秒要回话,现在是 11 个字段一次性摊开;
2. **待发片必须逐单进详情**——拍完回家批量处理时,一单 2 tap 进 + 1 tap 标 + 返回;
3. **"随时要用"的信息看不到**——日历页不算收入、地点不能拷/不能导航、搜索只认商家名。

补这三处即可用很低成本把"够用"提到"顺手"。其余(催收痕迹、平台到账、周视图)属周/月级痛点,排在后面。

## 2. 口径盘点(评估的前提:数据是够的)

- **工作线四态**:待拍摄 → 后期中 → 发片中 → 已交付(`logic.js` 77-82);里程碑五节点=拍摄/提审/副片/正片/发布,该单不要求的片自动从进度条消失(`openDetail` 1261-1264)。
- **资金线四态**:待定金 / 待尾款 / 平台结算 / 已结清(`logic.js` 101-106)。逾期**从实际拍摄日起算**(109-112),抖音商单永不计逾期(115)。
- **24h 未出片**:`deliverLate`(`logic.js` 85-87)驱动本地通知 + 列表红标。
- **排期冲突**:同日 ±120 分钟给提示、不禁止(`apptOverlap` `logic.js` 137-143;`updateConflict` 1023)。
- **导出**:CSV 25 列已覆盖全链路(934)+ 流水段;JSON 备份含账号与随手拍;`.db` 归档。

结论:**口径齐全,缺的几乎都在"取数路径"和"取操作路径"上,不在数据模型**。这意味着下面这些改法大多不需要动表结构,是纯增量。

## 3. 现在做得好的地方(改进时别改坏)

1. **首页只回答两件事**:今天拍什么、谁欠我钱。告警卡三态(逾期/已设提醒/健康)一眼定性,点进即催收清单(1426-1447)。
2. **详情页永远只给一个主按钮**:`detailActions` 按状态只返回下一个该做的动作(1248-1256),不需要用户判断"现在该点哪个"。
3. **拍照即打卡**:随手拍一次同时完成"到店证明 + 标记已拍摄 + 金额格铺底图",省一次点击(`imaging.js` + `priceCell`)。
4. **收款默认值合理**:默认微信;抖音商单单默认"平台结算",且不进入催收池——不用用户解释规则(`openPay` 1194)。
5. **催收有"别再烦我"的出口**:1/3/7 天 snooze 后首页不再红,只留一条灰提示(`snoozed` `logic.js` 119-121)。
6. **冲突只提示不拦截**:符合达人档期不由自己定的现实(1023)。
7. **多账号零打扰**:单账号时选号区根本不出现;≥2 才出单选卡,默认预选第一个(`openNew` 1035)。

## 5. 交互原则(后续版本的判定尺)

1. **一屏一决策**:首页只回答"今天做什么"和"谁欠我钱",新增信息要能进告警卡或速览格。
2. **高频动作 ≤ 2 tap**:能在行内做的,不要放进详情页。
3. **录单零键盘**:能默认就默认、能点选就点选;次要字段可折叠。
4. **状态尽量自动推进**:已经做到"拍照=已拍摄",可以继续往"发布后按日推断"走。
5. **钱必须可逆**:任何一键记账都要有一步撤销。
6. **信息随手能拿走**:地址、账号资料、账单都要能一键拷贝或导出。

## 7. 建议的下一步顺序

1. **P0-1 / P0-3 / P0-4**(半天,纯增量、不碰模型)—— 立刻提升"随手要用"的手感
2. **P0-2 行内动作**(1-2 天)—— 收益最大,直接决定"拍完回家"这一段顺不顺
3. **P0-5 + P1-9**(半天,改文案与取数)—— 消除误读
4. **P1-6 / P1-7**(要小改模型与迁移)—— 催收痕迹 + 平台到账
5. 以上稳定后再谈视觉与周视图
