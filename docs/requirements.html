Design Reconstruction · Three Directions

让每一单，
都有下一步。

这是一份从现有 TanJi Native 反推出来的设计文档：先看清产品已经成立的骨架，再用三套不同气质，重新回答“今天拍什么、这单走到哪、钱到了没”。

01

Summary · User · Value

不是表格，是达人的经营动线。

探记把散落在微信、相册与备忘录里的档期、交付和回款，收进一条本地、可追踪、可撤销的订单闭环。

01 / TODAY

今天先做什么

首页只回答两件事：今天拍什么、谁欠我钱。时间、地点、下一个动作必须比装饰更早被看见。

02 / NEXT

这单走到哪

拍摄、提审、正副片、发布是一条工作线；详情页始终只推一个由状态推导出的主动作。

03 / MONEY

钱到了没

定金、尾款、平台到账与催收是另一条线。任何一键记账都要能撤销，金额在任何页面都能隐藏。

核心人物

“我不是想记更多，我只是想知道现在该点哪一下。”单人 / 小团队探店达人 · 多平台账号 · 高频移动办公
现有替代方案

微信承接谈单，相册保存成片，备忘录记尾款，聊天记录提醒催收。信息很多，但“下一步”和“还差多少钱”需要用户自己拼。

设计目标

北极星
每周按时闭环的订单数：既完成发布，也完成收款确认。
行动效率
打卡、提审、发片、收款等高频动作保持 ≤ 2 tap。
录单目标
常见订单 30 秒内记完；次要字段可后补，不强迫一次填满。
信任目标
数据默认只在本机；备份、撤销、隐私模式与失败反馈可见。
反指标
不以停留时长、通知打开率、页面数量作为设计成功标准。
关键产品判断

探记不缺更多卡片，缺的是更清楚的注意力顺序。三套方案共享同一业务骨架，只在视觉气质、信息密度与反馈方式上分叉；任何方向都不新增账号体系、云同步或复杂经营分析。

说明：本节用户与目标属于基于代码和现有产品文档的反推假设，不等同于真实用户访谈结论。文档中的“现有事实”与“设计提议”分别标注。

五个目的地，两条推进线。

现有五 Tab 已经覆盖行动、排期、找回、资金与复盘。设计刷新不重画信息架构，只让每条路径更短、更稳、更可解释。

五条核心旅程

  1. 微信接单 → 建预约

    先记商家、时间、价格；服务商、账号、出片要求用点选与默认值补齐。

  2. 到店 → 拍摄打卡

    首页行内打卡或详情随手拍；拍照同时写拍摄时间，定位失败不阻塞。

  3. 回家 → 批量交付

    待发片列表直接提审、发正片、发副片、发布，不逐单进出详情。

  4. 发布 → 收款

    详情或收款页确认定金 / 尾款；成功后提供撤销，默认渠道保持微信。

  5. 逾期 → 催收

    首页进入催收清单，1 / 3 / 7 天备忘升级为本地通知，跟进痕迹可回看。

工作线

WORKFLOW
拍摄→提审→副片→正片→发布

正片 / 副片按订单要求显示；送审结果与发布时间可标记、可清除。

资金线

PAYMENT
待定金→定金已收→待尾款→已结清

抖音商单走平台结算，不进入催收池；逾期从实际拍摄日起算。

视觉延续 · P0

识别资产

3px 账号色条迷你头像门口照淡底金额格状态胶囊单一实心主行动

明确不做 · Scope

不借设计扩权

  • 不做云同步、社交、交易市场
  • 不做复杂 BI 与多端协作
  • 不用实时地图或持续动效抢注意力
  • 不为“原生感”加入无意义下拉刷新
03

Three Directions · Comparison

同一副骨架，三种性格。

A 延续现有产品的高效与亲和；B 把经营记录变成克制的编辑部账本；C 为夜间、户外与单手场景做一块低干扰仪表盘。

推荐

首版选 A，把 B 作为品牌升级候选，把 C 作为系统深色模式候选。三者不是三套需要同时维护的皮肤：A 负责把现有体验做顺，B 提供更鲜明的品牌上限，C 解决真实环境下的可读性与单手操作。

03 / DETAIL唯一主行动
01

风险先于内容

逾期卡只在有真实逾期时出现；健康状态使用低饱和完成色，不制造红色噪声。

02

照片不是装饰

门口照淡化成金额格底图，同时承担“已到店”证明；数字仍保持足够对比。

03

动作就在行尾

待发片直接显示“待正片 / 发副片”等下一步，避免逐单进入详情再返回。

04

卡片轻一点

双层近距阴影替代品牌色发光；按压只做 0.985 缩放，不做弹跳。

05

详情只推一步

发布是当前唯一主行动；收款是次级但清晰的资金动作，不抢工作流焦点。

06

迁移最温柔

保留现有橙色、胶囊、卡片和五 Tab，用户无需重新学习产品结构。

为什么好看

暖白降低纯灰工具感，珊瑚橙提供亲和识别，照片让订单从“数据行”变成“真实到店”。

要控制什么

卡片不能越加越多；标签不能缩到不可读；照片不能压住金额；主按钮全屏只能有一个。

05

Direction B · Field Notes

青墨编辑部。

把探记从“表格工具”往“经营手记”推一步：纸张色承托内容，青墨建立秩序，宋体标题让每家店像一条值得记住的新闻。

克制、可读、有品牌辨识适合品牌升级与长时间阅读

03 / DETAIL工作 × 资金账页
01

标题像刊头

日期、店铺名与章节使用宋体；正文仍用系统无衬线，避免“全宋体”造成阅读疲劳。

02

细线替代重卡片

分隔线、留白和字重层级承担 grouping，减少每个区块都浮起来的 SaaS 感。

03

金额像账页

数字右对齐、宋体放大；报价、已收、待收保持同一基线，变化一眼可见。

04

行程像议程

月历缩小为导航，单日内容用“时间 — 店铺 — 地点”的编辑式列表展开。

05

照片更克制

照片只承担事实与氛围，不铺满整屏；没有照片时用店名首字水印补视觉锚点。

06

动效像翻页

220–280ms 淡入与 8px 上移，不做弹性缩放、视差和持续背景运动。

为什么好看

纸色与青墨建立稳定的品牌气质，宋体标题让订单有“被记录、被讲述”的郑重感。

要控制什么

小字号宋体在 iOS 上易糊；标签不能只靠细线区分；长店名必须允许两行，不能强行单行。

06

专注、低光、单手可达推荐作为系统深色模式与户外场景候选

03 / DETAIL拇指热区
01

深色不是纯黑

夜海与面板分层，避免纯黑 OLED 上边界消失；正文保持柔白，不追求刺眼纯白。

02

只点亮当前步骤

薄荷绿只用于当前动作与完成状态；杏橙用于现场提醒，不做全屏霓虹。

03

主操作靠近拇指

打卡、发布等高频动作放在底部安全区上方，单手可达，不在页面顶端远处。

04

路线感而非地图

用抽象路径与站点表达行程顺序，不引入实时地图、定位持续耗电或外部依赖。

05

隐私一键切换

沿用现有全局隐私模式；深色模式不自动隐藏金额，但提供显眼的一键入口。

06

动效必须短

100–140ms 的即时反馈；禁止循环呼吸、背景流光和超大幅位移动效。

为什么好看

深色面板与薄荷绿形成清楚的夜间识别，路线抽象图让行程页有设备感而不是后台感。

要控制什么

深色下照片必须压暗并加文字遮罩；状态不能只靠颜色；系统深色与手动主题要避免重复开关。

07

Shared Interaction · Motion · States

三套皮肤，一套手感。

方案可以改变颜色与排版，但不能改变肌肉记忆。导航、撤销、弹层、手势与失败反馈必须共享同一套规则。

现有事实与设计提议共用一张交互规格表
交互触发与阈值反馈约束
Tab 切换单击底部 Tab内容 120–180ms 淡入；选中图标与文字同时变色不增加第 6 个 Tab；不做整页横向滑动
订单行点击单击卡片 / 行按压 0.985；详情从底部展开行内按钮不触发父行点击
行内推进点击“打卡 / 提审 / 发片 / 发布”立即更新状态；涉及资金时 toast 带撤销不为高频动作强制进入详情
随手拍详情或首页进入相机拍摄成功即写 shotAt；定位尽力获取定位 / 相册失败不能挡拍摄状态
弹层下拉现有规则：位移 >110px 松手关闭跟手位移；未过阈值弹回仅头部 / 把手或列表滚到顶时接管

A / 160–220MS

轻快工作台

短促缩放与淡入；卡片像被按下，金额 toast 不做弹跳，避免“钱在跳动”的轻浮感。

B / 220–280MS

编辑式翻页

淡入与 8px 上移；章节切换像翻页，不做视差、透视与连续动画。

C / 100–140MS

仪表确认

快速状态切换与轻微 haptic；当前节点可短暂提亮，但不循环呼吸。

所有方案共享：44 × 44 pt 最小触控目标、iOS 安全区、Dynamic Type、VoiceOver、颜色 + 文字双编码、减弱动态效果。网页文档中的手机模型仅用于视觉评审，不代表真机尺寸测量结果。

08

Empty · Loading · Error · Accessibility

空状态也要有下一步。

本地 App 的异常不一定是网络问题，更多是空数据、权限、写入与状态边界。每个状态都要说明发生了什么、数据是否安全、现在能做什么。

三套方案共享的状态矩阵
状态界面表达主动作不能做
今日无单“今天没有拍摄安排” + 下一站摘要查看行程 / 新建预约不显示虚假待办
今日已拍完保留全部订单，已拍行置灰并显示完成时间查看待发片不随打卡减少今日总数
待发片为空“都出完了” + 本周完成数查看订单 / 统计不放庆祝动画刷屏
收款健康低饱和完成卡：“暂无逾期”查看待收不继续使用红色告警
加载保留列表与日历结构的 skeleton等待；超过 1 秒给出进度文案不整屏 spinner 遮挡结构
离线核心功能正常，不显示打扰横幅继续记账、打卡、查看不把本地优先说成同步失败
定位拒绝不弹阻断错误；详情显示“位置未记录”继续打卡 / 手动补记不因为 GPS 失败丢拍摄状态
照片权限拒绝情境化说明，保留已填字段打开系统设置 / 返回不清空表单
写入失败原位错误条，说明未保存重试不显示成功 toast
隐私开启所有金额显示为遮罩或圆点再次点击眼睛恢复不在分享图泄露未选择金额
大字体卡片纵向扩展，按钮保持可见继续滚动完成不截断店名、状态、金额
减弱动效关闭位移、骨架闪光与状态脉冲直接切换不保留无限循环

Accessibility

看得见，也听得见。

  • 语义：订单行朗读“店名 + 时间 + 工作状态 + 资金状态”。
  • 触控：所有可点击区域至少 44 × 44 pt，行内按钮留足间距。
  • 对比：正文 ≥ 4.5:1；大数字 ≥ 3:1；深色方案单独测量。
  • 颜色：逾期、完成、待处理都同时有文字与图标，不只靠红绿。
  • 字体：支持 Dynamic Type；AX5 下关键操作仍可达。
  • 焦点：弹窗关闭返回触发按钮；页面切换焦点到标题。
  • 动效：尊重“减弱动态效果”，无持续背景动画。
  • 横向内容：未来 7 天、账号筛选提供滚动提示与替代入口。

Quality Budget

质感不能拿性能换。

启动
建议目标：常用设备冷启动首屏 ≤ 1.5 秒；需真机实测，不以文档承诺。
滚动
100 单样本下首页、订单、行程稳定；只加载门口照缩略图。
图片
沿用 256 × 128、约 3KB 的门口照处理，不把原图塞进列表。
包体
本设计文档零外部图片、字体与 CDN；视觉稿不引入 3D 引擎。
隐私
无账号、无广告、无分析 SDK；导出前明确内容与金额范围。
可测
视觉验收与业务回归分开；真机验证手势、安全区和权限。
09

Requirements · Acceptance · Decision

以可验证的结果交付。

以下标准同时约束三套方案。它们不要求一次做完三个主题，而是保证无论选哪套，产品骨架、资金安全与移动体验都不退步。

Given / When / Then 设计验收
编号验收标准
AC-01Given 任一方案，When 切换五个 Tab，Then 入口名称与顺序不变，当前账号筛选状态符合现有规则。
AC-02Given 首页有逾期，When 打开 App，Then 逾期卡先于待发片与速览出现；无逾期时不出现红色卡。
AC-03Given 待发片订单，When 在首页或订单列表操作，Then 可直接完成下一步，无需先进入详情。
AC-04Given 详情页，When 状态变化，Then 只出现一个实心主按钮，且文案来自当前 nextStep。
AC-05Given 一笔收款，When 确认成功，Then 出现可撤销反馈；撤销后金额、流水与提醒同步恢复。
AC-06Given 隐私模式开启，When 浏览五个 Tab 与分享图，Then 未明确选择的金额不泄露。
AC-07Given 多账号，When 使用全部合并视图，Then 行首 3px 色条与迷你头像同时可辨，不整行铺色。
AC-08Given 照片权限或定位失败，When 用户尝试打卡，Then 不丢失已填内容；定位失败不阻断拍摄状态。
AC-09Given 表单弹层，When 内容超过一屏，Then 保存条始终可见，下拉关闭只从允许区域接管。
AC-10Given 200% 字体与 VoiceOver，When 浏览核心页面，Then 店名、状态、金额与主操作可朗读且不遮挡。
AC-11Given 方案 A，When 展示首页与详情，Then 暖白 / 珊瑚橙体系一致，门口照淡底不压金额，卡片无品牌色发光。
AC-12Given 方案 B，When 展示行程与详情，Then 宋体只用于标题与关键数字，正文保持系统字体，细线不承担唯一状态编码。
AC-13Given 方案 C，When 展示深色页面，Then 正文与按钮对比达标，照片有遮罩，无循环动画与纯黑大面积边界。
AC-14Given 开启减弱动态效果，When 切换页面、打卡、发布，Then 无持续动画、明显位移或闪烁。
AC-15Given 100 单本地样本，When 冷启动并滚动核心列表，Then 视觉层不引入原图解码、外部请求或持续内存增长。

设计风险

风险概率影响缓解
A 卡片继续堆叠中高首页只保留两类任务与一组速览。
B 宋体小字可读性下降中中宋体限标题与数字；真机测大字体。
C 深色照片吞掉文字中高固定暗色遮罩与独立文字层。

建议决策

D1 · 默认方向

先落 A

迁移成本最低，能立即改善现有首页、详情与状态反馈。

D2 · 品牌上限

评估 B

若希望探记从工具升级为个人品牌，B 是最值得继续深化的方向。

D3 · 深色策略

Definition of Done

三套方案的页面骨架、状态矩阵、交互规则与 AC-01 至 AC-15 对齐；选定方向后完成真机对比，再进入视觉实现。本文件本身不修改任何 App 页面、数据、权限或发布配置。

10

Evidence · Facts vs Proposals

从代码来，向设计去。

“现有骨架”来自仓库事实；“三套方向”是设计提议。两者在文档中分开陈述，避免把美好想象误写成已经上线的能力。

现有事实

  • 产品：探店达人的行程 + 收款工具，Capacitor 壳复用 Web UI，iOS 本地 SQLite。
  • 结构：首页 / 行程 / 订单 / 收款 / 统计五 Tab。
  • 工作流：拍摄 → 提审 → 正副片 → 发布；送审结果可标记。
  • 资金：定金 / 尾款、平台结算、逾期催收与本地通知。
  • 原生手感：禁缩放 / 长按选择 / 橡皮筋，弹层下拉关闭。
  • 隐私：纯本地、无服务器、JSON 备份、金额隐私模式。

设计提议

  • 方向：暖橙工作台、青墨编辑部、夜航仪表。
  • 视觉：三套 token、首页 / 行程 / 详情高保真示意。
  • 交互：共享手势、动效、状态与无障碍规则。
  • 决策：首版 A、品牌候选 B、系统深色候选 C。
  • 边界：不新增云同步、社交、地图 SDK 或经营分析。
  • 验证：先真机对比，再进入任何开发。
